# SCT foundation validation — Inspector v0.1.14

## Passed in this environment

- Syntax validation (`node --check`) of all extension JavaScript and the offline regression runner; JSON parsing of manifest and schema; referenced extension files present.
- Existing Inspector network bridge, ordinary export/report implementation and permissions checked against the preceding consolidated 0.1.14 package. The new recorder is opt-in; ordinary controls and stored events are separate. The ordinary settings write path now serializes changes to avoid losing simultaneous SCT/ordinary settings updates.
- Offline Node harness: strict allowlists for creation routes/endpoints, rejection of private chat, history, auth and unexpected hosts; sensitive field/query/header/body omission before SCT persistence; untrusted page events cannot become operation markers; mode gates; full-mode expiry; exact peer identity and origin checks, tab scope, operation UUID and conflicting base correlation; positive/negative marker acknowledgements, duplicate and conflicting sequences; disabled transfer and destination validation.
- Mock DOM/isolated capture: disabled creates no SCT listeners/observers; active editor observes structural state, Save attempts, request submission, HTTP 429, validation and watchdog interruption; stop flushes and removes listeners; new document stream resumes the same recording. No actual save or API action is made by the module.
- Asynchronous **mock IndexedDB** harness: batch commit/deduplication/drop counters, 1,000-row cap with 100 excess rows dropped, persisted state across re-created worker/store instances in the mock, expiry cleanup. This does not establish browser transaction durability or real restart behavior.
- Real historical recording replay (`spicychat-inspector-2026-11-26T11-48-10-711Z.json.gz`): 25,063 input events; 2,498 projected creation-network observations including 1,184 HTTP 200 Lorebook entry creation responses and 1,313 reads; no synthetic verification events inferred. Existing capture's network metadata is reused read-only. This is offline replay, not a new live recording.
- Synthetic 50,000-row summary computation; all 25,000 paired request/response keys resolved in the fixture. Node execution time varied between runs; not a browser performance benchmark.
- Synthetic click/request association, missing sequence, unresolved write, expected/observed mismatch, and completion without reported verification tests.

Run `node tests/sct-selftest.cjs` from the unpacked extension on Node 22+. Optionally pass the exact historical recording named above to replay that fixture. The historical recording is not bundled. The test runner uses mocked runtime, DOM and IndexedDB APIs, not a real extension environment. No network traffic is generated by the runner.

## Not verified / blockers

The supplied Chromium environment blocked extension pages, `chrome://extensions/` and both external and localhost synthetic-page navigation (policy / administrator restriction). The unpacked-extension and actual-browser test attempts could not run. No policy was changed or bypassed. Real service worker startup, cross-extension `sender` fields, actual IndexedDB durability, UI rendering/download, simultaneous ordinary recording, renderer recovery, full browser restart, seven-day session behavior, 100,000-row global capacity, Firefox/Orion compatibility and real mobile performance remain to be verified. GZIP export is implemented using the same Blob/CompressionStream pattern as the existing Inspector, but actual download has not been verified in this environment.

Rulebook/group, chatbot create/edit, attachments, moderation and publication endpoints are conservative allowlisted candidates; the current offline fixture confirms Lorebook operations only. Obtain sanitized real recordings for remaining routes. More detailed operation phases require QoL/Creator Tools journal markers. No backend transport is enabled or tested against an actual endpoint, no publication account was accessed, and no extra SpicyChat API requests were sent.

## First live validation recommended

1. Load the complete unpacked 0.1.14 SCT foundation in a test Chromium profile; refresh existing site tabs. Verify the normal build check and ordinary recording while SCT is disabled.
2. Start a scoped SCT editor recording with ordinary capture paused; perform one normal manual Lorebook edit and export. Verify attempts, requests, observed outcomes, no authored content and correct counts. Repeat with ordinary capture enabled simultaneously.
3. Enable the authorized QoL peer ID for a publication-mode recording; use harmless synthetic journal markers, validate committed acknowledgements and rejection of a wrong peer or duplicate/conflicting sequence. Verify actual runtime sender URL/origin behavior.
4. Test browser and extension reloads, explicit stop, expired retention and larger imports with existing pacing. Test chatbot/Rulebook/group/attachment and moderation flows through ordinary permitted use; verify routes/response shapes and precise status semantics.
5. Only after those tests, deploy on a dedicated browser profile if desired. Backend transfer remains disabled until a separate authenticated endpoint and transport contract exist.
